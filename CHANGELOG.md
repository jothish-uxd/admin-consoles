# Changelog

## v0.2.3 preview — 2026-11-23

### Added
- **MCP connectors**, a new category in Governance & compliance with 8 patterns: *Approving connectors* (connect, test, review the tools, then publish; catalog and custom servers alike), *Choosing tools* (allow, ask first or block each tool, with write and delete tools opt-in), *Sign-in & credentials* (each person signs in, or one org connection, and why it matters), *Who gets each connector* (by group, role or person, with pilots), *Allowed connectors* (approved only, or any server, and the risk of rogue servers), *Data leaving the org* (what goes out, where it runs, and outside AI tools reaching in), *AI activity record* (every tool call with the person and the AI client) and *Health & revoking* (failing sign-ins, and one switch to turn a connector off everywhere). Real-world examples from Glean, Grok and Atlassian. 24 categories, 124 patterns.
- **MCP connectors clips:** *Approving connectors* (the admin adds one herself: search the catalog, with Verified partner and Community · not reviewed labels and Add by URL; the draft with where it runs and an unreviewed warning; connect a test account and see 6 tools grouped as read, write and delete; a test call with its result; a draft until a separate Publish step: everyone in Echo Base or selected groups, and which tools are on) and *Choosing tools* (the Tools tab; every tool in plain words, grouped, with where it's on; Allowed · Needs approval · Blocked per tool that people can't override; a tool the server added later held off until reviewed, then set to Needs approval with what that means). The connector page is shared through `motion/shared/connectors.css`, so it's the same pixels in both. The prototype has the same pages under AI › Connectors. Then three more: *Sign-in & credentials* (the Sign-in tab; three choices explained before they're chosen, per-person recommended; One org connection warns that actions show the shared account; org-managed sign-in through the identity provider, tested; what people see when they connect; the secret masked), *Who gets each connector* (the Access tab; a pilot note; groups, a role and a person exception; Add group, then tools narrowed to read only with visible Add and Cancel; the exception says it overrides the group; what everyone else sees) and *Allowed connectors* (the policy pill opens Connector policy; Off · Approved only · Any server with Recommended in words; Any server asks for confirmation with the risks; the approved list with owners; Enforced in, with coding tools turned on; what people see when a server is blocked). The Fleet Tracker clips are built from one page by `motion/_build/`, so the header, tabs and Overview match to the pixel. And the last three, so every MCP connectors pattern now has a clip: *Data leaving the org* (the Data tab; where it runs, what it sends and how long the provider keeps it; where residency and Echo Base's AI policy stop; only what the tool asks for; Restricted added to labels never sent; outside AI tools that can reach Echo Base, with API tokens off), *AI activity record* (the Audit log, same page as the audit clips, filtered to AI tool calls; the person and the AI client on every row; a shared account and a failure in words; admin changes in the same list; a summary line; Export → JSON) and *Health & revoking* (statuses in words with the last good call; people who need to sign in again see Reconnect; a failing connector's health and what changed in its tools since approval; Turn off for everyone, confirmed with who it affects, signing everyone out, applying everywhere within 10 minutes). The prototype has the Data tab, AI tool calls in the audit log, and health with Turn off for everyone.
- **Destructive actions clips**, all 6: *Delete confirmation* (three files picked from the Owner deactivated view; a dialog that names them, says 3 public links stop working and 14 people lose access, and that Trash keeps them 30 days; focus on Cancel and a red outlined Delete, not the default), *Type-to-confirm* (Delete sandbox, kept for the rare unrecoverable action; what goes; the name to type, with Copy name; Delete off with its reason until it matches; capitals and spaces don't matter, and Matches is announced), *Archive vs. delete* (Archive group first in the row menu, Delete group… below a divider; what archiving keeps; delete for good as a small link; an Archived filter and a text label; Restore), *Undo toast* (Move to Trash from the row with no dialog; a toast with Undo and a 10-second timer that pauses under the pointer; the row back in place), *Cascading impact* (what depends on Content admin, grouped as Detached, Deleted and Breaks; Delete off while Holonet sync would break; give the 8 people Viewer, switch the integration, then delete) and *Danger zone* (routine settings first; a bordered Irreversible actions section only owners see, one row per action with what happens; Reset all public links with a plain confirm; the delete rows ask for the name). Pages are reused to the pixel: Content › All content now has a select column (Asset library re-rendered) and People › Groups a ⋯ menu with Hoth Evacuation (Create modal re-rendered); a new Settings › Organization page is shared by Type-to-confirm and Danger zone. The prototype has all of it: select and delete with a confirmation, Move to Trash with a pausable Undo toast, a Trash tab with Restore, archive and restore groups, a role delete that lists what depends on it, and Settings › Organization with the danger zone and type-to-confirm.
- **Audit log filter buttons** (time range, Actor, Action, Target, Result, IP) now carry the shared dropdown chevron, like every other dropdown in the clips. Audit log table, Event detail, Filters & saved views, Export & SIEM streaming and AI activity record re-rendered.
- **"What happens in this clip"** now sits above the clip, still collapsed, so the steps can be read before playing.
- **Plan overview** re-made: one steady view of the whole plan page instead of zooming and panning card by card (which drifted past the window's edge), and 9 seconds instead of 15. Short clips now run at their natural length, up to 10 or 15 seconds, rather than being stretched to fill it.
- **Edit & bulk actions clips**, all 5, each only as long as it needs (9–14 s): *Selection model* (named row checkboxes; shift-click for a range; the header checkbox selects this page and says so; Select all 82 matching), *Contextual action bar* (a bar above the table in the results line's place; count and Clear, common actions, Suspend last behind a divider; Suspend turns off in place with the reason when a deactivated person is selected), *Bulk edit* (field first, with Team off because it's synced from HR; Add to existing · Remove · Replace all · Clear in plain words; current values as Various; a before and after preview; a button with the count), *Inline edit* (a pencil on the name only; Save and Cancel plus Enter and Esc; a slash refused with the field kept open; Saving…, then Saved on the row) and *Progress & results* (a job above the list with counts and an estimate while the page stays usable; Done with issues with added, skipped and failed and the reason; Retry failed on just that one; results stay until dismissed). A new People › Users page is shared by four of them. The prototype has all of it: select with shift-click and select all matching, the action bar, the bulk edit dialog, a running job with results and Retry failed, and rename in place on Content. Clips without a fixed length now run their natural length instead of being cut at the end of their timeline; Plan overview is re-made to 9.7 s with its end card.
- **Decisions & trade-offs**, a new tab trialled on *Access requests & approvals*, after Scale. For each pattern: the core trade-off, when to use it, when to avoid it, alternatives with when to pick each, and common implementation mistakes. It follows the pattern chosen on the Patterns tab, and links as `#decisions`. Content lives in `data/decisions.js`; categories without an entry have no tab.
- **Trial layout on *Access requests & approvals***: an overview (intro, which patterns you need by size, principles that span the category), then one complete view per pattern: clip, *Should you use it?* (trade-off, when it starts to pay off, use it when, skip it when, alternatives), *How to build it*, *At enterprise scale* and that pattern's real-world examples. No tabs. `?layout=current` shows the tabbed layout to compare.

## v0.2.2 preview — 2026-11-21

### Changed
- **Sidebar counts** show each category's number of patterns instead of screens, in both *By group* and *A–Z* (screen readers hear "5 patterns").
- **Sidebar credit** is now two lines: **Patterns for Enterprise Admin Consoles**, then Jothish John · © 2026.

### Added
- **Pattern clips.** A short clip can sit above a pattern's card on the Patterns tab. The first one is *Access requests › Request access*: it starts on the access-denied page, asks what the person needs to do rather than which role, shows an example reason, confirms who the request was sent to and offers Follow up and Cancel request. It's a 15-second walkthrough in a mock Echo Base console that ends on a grey credit card, with small interaction sounds and no music. The end card is silent. It waits on its first frame with a play button and never starts on its own; A player bar runs along the bottom: play / pause, elapsed and total time, a timeline you can drag, click or step with the arrow keys, sound on / off and full screen. While a clip plays, the bar fades if the pointer rests and comes back on movement or keyboard focus. *What happens in this clip*, a collapsed grey accordion under the clip, lists the steps as text. When a clip ends, a grey end card shows the replay button with the credit (**Patterns for Enterprise Admin Consoles** / Jothish John · © 2026) centred in its lower half. Sound on / off is remembered in your browser. In every clip the signed-in user is Lavanya Sienna, with a Star Wars title that fits the scene (Jedi in training when she asks, Jedi Master when she approves).
- **One console across all clips.** Every clip uses the same rail (Workspace · Admin) and breadcrumb, drawn from one shared map; motion/CONSOLE.md places all 116 patterns in it. All 11 clips re-rendered.
- **Clips follow their cards.** Each clip shows the card's guidance and nothing that contradicts it; the scene file lists which card points each moment covers.
- **Clip length:** clips with fewer than 5 steps run 10 seconds, and those with 5 or more run 15, including the end card. The extra time goes to the moments that matter: every click, and key beats such as the high-risk tooltip, which the camera also zooms in on.
- **Access requests clips:** *Request access*, *Approval queue* (oldest-first queue, an escalation warning, bulk approval for low-risk requests only, a single high-risk approval from its row, and Undo), *Review detail* (who's asking, what they'd get in plain words, peer context and an unusual-request flag, narrowing scope and duration, a required comment, and the decision record) and *Time-bound access* (end times in local and relative time, a warning before expiry, a one-step extension that keeps the original reason, and automatic, logged revocation of a just-in-time grant) and *Access reviews* (a campaign with a deadline, progress and reminders, risky and unused access first, suggested decisions, keyboard shortcuts, automatic removals and saved audit evidence). Every Access requests & approvals pattern now has a clip.
- **AI governance clips:** *Feature availability* (every AI feature in one place with plain descriptions, status in words and adoption; new features off until turned on, with a heads-up banner; a pilot widened by group; what people see when it's off; an org-wide off switch) and *Data usage controls* (direct answers first on training, retention and location; a named link to the terms and notice of changes; retention with its consequence; sensitive labels excluded from every AI feature; residency by region; logged changes) and *Model & provider settings* (Recommended models as the default; a change announced ahead; a comparison table with plain descriptions, trade-offs and data location; approved models per region; what changes when a model is removed; logged, with each answer recording its model) and *Usage & cost* (credits against budget and time saved; a labelled trend and forecast with a text summary; groups by cost with a spike flagged; a per-group budget with an alert; what happens at the limit, without cutting off tasks; export for finance) and *Content safety* (built-in protections always on; filter strength explained; an org blocked topic added; what people see when blocked, and why; reports grouped and resolved with a saved record; settings per region). Every AI governance pattern now has a clip.
- **Asset management clips:** *Asset library* (one searchable inventory with index freshness and approximate counts; filters and saved views; owner, sharing and last activity on every row; list and grid, with no previews by default; exports as background jobs) and *Asset detail* (why the admin is here; a logged admin view that doesn't open contents; details as a description list; access by route in words, including link and inherited; recent activity linked to the audit log; admin actions together; removing a public link with its consequence) and *Transfer ownership* (starts from the person's offboarding checklist in People, with delete locked until content moves; everything in one go, to the suggested manager; deactivated and external recipients blocked with reasons; sharing kept and said; a named folder and a summary for the new owner; confirm, background progress, failures with reasons, and reassign) and *Sharing controls* (what's shared outside now; options from most to least restrictive with the recommended one marked; the impact on existing links before a change, rolled out over time; link expiry, passwords and a narrow default; exceptions and which one wins) and *Versions & restore* (the Versions tab as the way in; versions with time, author and a note; retention shown; compare before restoring; restore as a new version that keeps the current one; folder restore to a point in time; logged). *Tags & metadata* finishes Asset management (the Tags tab as the way in; counts per tag; near-duplicates merged as a job, kept as synonyms; managed fields; auto-tag rules with exceptions). Clicks now stay clear of the site's player bar: `motion/audit.py` checks every scene, and Feature availability, Request access and Versions & restore were re-framed. Audit logs & activity starts with *Audit log table* (a Home alert as the way in; events as sentences with codes secondary; actor types; absolute PT times with exact time and UTC on hover; failures kept and written out; filter by clicking the actor; 24-hour range, 50 of 18,204, Next 50). *Event detail* follows on from it (a failed event with why and context; related events by actor, session and key; the settings change with before/after and text labels, secret not shown; Raw JSON with schema version and redaction). *Filters & saved views* continues it (filters kept on coming back; quick and detailed filters with a query line; bounded time ranges with a labelled custom range and background runs; count announced; a saved view shared with Security admins; link with filters). *Export & SIEM streaming* continues it (export of the view as JSON, ordered and versioned, limited by role, logged; streams with health in words; a delayed S3 stream that buffers and replays in order; filtered streaming). *Alerts on events* completes Audit logs & activity (built-in alerts with thresholds; a muted alert with its record; an alert from the saved view with an example threshold, destinations, routing and grouping; history as a sentence with a link to the events). Billing & licenses, all 4 as one story: *Plan overview* (price with currency and tax, renewal in words, seats by product, what Enterprise adds, cost by department, finance view-only), *Seat assignment* (who has which license and why, reclaim 14 inactive with notice, data kept and 30-day undo, counts match the plan), *Add seats* (live prorated price, no add-ons pre-selected, quote/PO path, review then buy, seats update now) and *Invoices & payment* (early card-expiry warning with a 14-day grace, named PDF links, statuses in words, billing details, card updated showing last 4 only). Pattern pages now link to their screenshots as "See N examples from real companies" instead of "See N screens in Screens". The category tabs are now *Patterns · Scale · Real-world examples*: the two guidance tabs sit together, and the Screens tab is renamed and moved last. Creation flows, first 3: *Create modal* (3 fields, duplicate name caught inline and fixed without losing values, Creating… disabled, new row highlighted), *Multi-step wizard* (a shared draft resumed; stepper with done, optional and unreachable steps; one question per step; review with Edit links, live checks and what happens next) and *Create from template* (org vs built-in with owners and versions, Start blank, text preview, values adjusted, policy records its template version). The rest of Creation flows: *Inline create* (a focused row with Enter/Esc, Saving… and Saved on the row, pinned as New, a duplicate rejected with the row kept), *Duplicate / clone* (choose what to copy with members off by default, secrets never copied, opens ready to edit as a marked copy) and *Success & next steps* (a job, then a lasting success panel with the required follow-up, three next steps, setup progress and the API call). Same page, same pixels: one shared page frame (title, header, tabs) for every clip, and pages that appear in several clips (Home, Billing, People, Content and its Tags tab, the item page, the Audit log) now have identical headers, tabs and toolbars, so nothing shifts between patterns. All clips re-rendered. *Inline create* now has visible Save and Cancel buttons on the row, with Enter and Esc as shortcuts, and its card says so (buttons and keys, not either). New clips meet WCAG AA contrast (the clips' lightest grey is now #737373, as on the site) and put labels above values (`.kv`); All 31 clips were then re-rendered to match: AA grey throughout (including placeholders and chart labels), labels above values in Plan overview, Add seats, Invoices & payment, Asset detail, Versions & restore, Event detail, Review detail and Sharing controls, one drawn dropdown chevron set 12px in from the right edge, and one shared panel for every open dropdown menu. The clickable Echo Base Console prototype (`prototype/`) has every screen from the clips; its dropdowns open the same drawn menu as the clips, with full keyboard and screen-reader support.
